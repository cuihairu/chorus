- `RedesignMatchTicketStore`（DataServer）：EnqueueTicketAsync 一个回执事务（键 `(tenant,game,"match.enqueue",bindingId,operationId)`，canonical v1 含 binding/session/partition/expires）；§6.5 锁序 Session→Binding→Ticket——校验链 auth.session 存在→streamer_state FOR UPDATE（当前会话+Allowed）→session 行 FOR UPDATE（未吊销未过期）→binding FOR UPDATE（租户/游戏相符、状态活跃、live session 属同一主播）→无 Active/Offline 参与→INSERT 'Queued'；`ux_match_ticket_active` 冲突（23505 按约束名识别）→可见拒绝「每挂载最多一个有效票据」。CancelTicketAsync（回执 match.cancel）：binding→活跃票 FOR UPDATE，Queued→Cancelled（version+1）；Reserved/Preparing→可见拒绝（预留事务先锁者胜）；无活跃票/Committed→可见拒绝；同 op 重试 Duplicate 回放。ExpireQueuedAsync：`FOR UPDATE SKIP LOCKED` 确定性 sweep（幂等于谓词），过期 Queued→Expired 释放唯一索引槽；ListQueuedAsync：协调者候选窗（单一 partition_key、排除已过期末扫票、created_at 序）；GetTicketAsync：挂载最新票状态读。

按架构 §7.2/§10.1「预留=term 门内一个事务锁全部候选」「预留持有容量至提交或回收」「过期预留的票回队、已开房释放，容量无永久泄漏」：

- `RedesignMatchReservationStore`（DataServer）：ReserveAsync 一个回执事务（键 `(tenant,game,"match.reserve",roomId,operationId)`，canonical v1 含 room/partition/term/排序后 participant 集）；§6.5 锁序 Coordinator→Binding→Ticket→Reservation——事务内 `control.coordinator` FOR UPDATE 校验 holder+term+租约，不符→`RedesignStaleTermException`（过期 term 永不预留，AT10）→ `pg_advisory_xact_lock('game.room:admission')` 与 M2 房间准入同锁：容量=非终态房间+`'Reserved'` 预留共享 `CHORUS_MAX_ACTIVE_ROOMS` 上限（拒绝计 `ops.capacity_rejection('reserve-match:active-rooms')`；保守双计：StartRound→MarkPrepared 窗口一票双占，宁少勿超，已注明）→候选 binding FOR UPDATE（活跃、无在局参与）→候选 ticket FOR UPDATE 必须恰为本 partition 一张 Queued（跨 partition 候选=错平台策略可见拒、已被预留拒、自过期拒）→INSERT `'Reserved'`（room_id 唯一冲突可见拒）→tickets→`'Reserved'` 带 reservation_id→outbox `match.reserved`。RenewReservationAsync：Reserved/Prepared 且未过期才可续，过期预留归 sweep 不可复活。MarkPreparedAsync：Reserved→Prepared，需 room ownership Active 未过期，`prepared_receipt jsonb` 落库=继任者凭证（AT11）。ExpireReservationsAsync（SKIP LOCKED sweep、无任期终结者——时间决定）：内联 AbortRound 释放骨架（参与 Closed→绑定指针清→房 Aborted→ownership Released epoch+1→outbox `{roomId}/0/abort`）+ tickets 回 Queued（自过期者→Expired）+ 预留 `'Expired'` + outbox `match.expired`。`crashAfterReservation` 注入缝留给 M3-4 杀协调者测试。

## M3-3 已落地：CommitMatch 原子提交与 AbortReservation（8d5aaab）

按架构 §7.2.5/ADR-R07「提交=一个事务内 term 门+ownership 栅栏+全票 Committed，一起生效或不生效」：

- `RedesignMatchReservationStore`（DataServer）新增：CommitMatchAsync 一个回执事务（键 `(tenant,game,"match.commit",reservationId,operationId)`，canonical v1 含 reservation/room instance/room epoch）——锁序 **Coordinator→Ownership→Reservation→Ticket**（RetireAsync 同对同序，提交与释放串行不互锁；预留给 M3-4 续作）：`control.coordinator` FOR UPDATE 校验 holder+term+租约→`control.ownership`（kind=room）FOR UPDATE 栅栏——行缺失/实例不符/epoch 不符/租约死/非 Active→`RedesignStaleOwnerException`（被换主的游戏进程永不提交，AT25 mechanics）→reservation FOR UPDATE（须 Reserved/Prepared 且未过期；过期归 sweep 不可提交）→tickets→`'Committed'`（同事务离开 ux 活跃槽）+reservation→`'Committed'`+outbox `match.committed` `{reservationId}/commit`（payload 含参与集与 room instance/epoch）。AbortReservationAsync（回执 match.abort）：term 门→RetireAsync(Aborted)：参与 Closed→指针清→房 Aborted→ownership Released epoch+1→outbox `{roomId}/0/abort` round.aborted、tickets 回 Queued（自过期→Expired）、outbox `{reservationId}/abort` match.aborted；已 Committed/已回收→可见拒。**RetireAsync 重构**：锁序改 Ownership 先于 Reservation（与提交一致，消除 AB-BA）；候选选择改无锁 SELECT+行锁下重校验（status 仍 Reserved/Prepared、sweep 模式再验 expires 已过——与续租竞态时跳过不误回收），返回是否实际回收；sweep 计数只计真回收。
- `m3.proto Match` 增 CommitMatch/AbortReservation（仅 control-server）；StaleOwner→FailedPrecondition「The room is fenced by another owner.」。
- 证据：store 级 +3 例（库族 chorus_m3_reservations_：提交栅栏——错 term/错实例/错 epoch 三拒+正栅栏提交全票 Committed+重试 Duplicate+二提交拒+已提交挂载再入队拒（在局规则）+过期预留持栅栏仍拒+outbox 恰一；**继任者续作**——Prepared 后协调者易主 term+1→继任者读冻结 reservation+prepared_receipt 凭证→同房提交成功不建第二房（AT11 核心）；撤销全释放——错 term 拒+撤销后房 Aborted/ownership Released epoch+1/票回 Queued/outbox round.aborted+match.aborted 恰各一+二扫 0+已撤销提交/再撤销双拒+容量槽位（cap=1）可再预留）+ host `RedesignM3HostTests` 扩全链（真实三进程：第二挂载经 control 证书入队→ControlServer ClaimOwnership→错 epoch 提交 FailedPrecondition→MarkPrepared→CommitMatch Committed+票 Committed→已提交撤销 FailedPrecondition；streamer 证书 CommitMatch PermissionDenied；1s 预留 sweep 只回收第一个）。Release 全量 1233→1236/1236。
