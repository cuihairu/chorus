## 2. 验收场景

| 编号 | 测试与故障注入 | 必须证明的结果 |
|---|---|---|
| AT01 | 合法主播启动、加载资料、登录、无匹配处理个人命令 | 实体独立可用；加载失败不返回 LoginReady |
| AT02 | 抖音/快手脱敏真实样本、伪造签名、过期凭据、错 AppId | 生产适配器符合实际直播协议；错误身份不能登录 |
| AT03 | 两终端同时登录、旧命令/断线晚到、resume 轮换提交后丢响应 | 单有效控制会话；旧新命令拒绝，精确重试不重复轮换，新连接不被误标离线 |
| AT04 | 跨 GameId 两个并发玩法启动、切换途中重启 | 共享直播槽仅一个活跃挂载；未验证跨应用直播键不能假称互斥通过 |
| AT05 | 旧局礼物跨新局到达，缺对局字段，绑定尚未建立 | 有可信线索归原局；无局标识按首次接收窗口固定归属；映射冲突待核对，无无限隔离 |
| AT06 | 对局中断网至接近局末，连接另一 Gateway；离线跨局末 | 原局继续并恢复；离线不自动排新局；结果可查 |
| AT07 | 回调持久提交前/后 kill，重复批次，部分批次错误 | 确认后的输入存在；重复不重复应用；整批回执语义正确 |
| AT08 | 礼物先于入队弹幕、乱序重试、相同金额两笔合法礼物 | 顺序固定可重放；合法两笔不被误去重；不假设平台真实全序 |
| AT09 | 外部调用发出后杀进程，结果超时且不支持幂等 | 查状态或 NeedsAttention；不盲目重复冲突调用 |
| AT10 | 两主播分别在两台机器登录，匹配到第三实例；错平台候选混入 | 同 RoomId、同权威 Tick、正确平台事件路由；Reserve/Commit 均拒绝平台策略不符 |
| AT11 | Prepare 前后、Commit 前后分别杀协调者/游戏进程 | 无半入场；预留或提交结果可恢复；容量无永久泄漏 |
| AT12 | 匹配取消、重复入队、双协调者 term 交错 | 每挂载最多一个有效参与；过期 term 无法提交 |
| AT13 | 100 房间基线+热点输入，单模块抛异常 | 报告 Tick/提交/CPU/WAL 分布；其他房间不被逻辑异常直接破坏 |
| AT14 | 每一提交边界注入连接中断、重试同 CommitId、并发低序号晚提交 | 无未持久帧被发布；FullCheckpoint 同事务；帧序连续，消费不越过空洞 |
| AT15 | 慢客户端、ACK 丢失、delta 基线缺失、队列爆满 | 其他客户端继续；慢端全量追上；不应用不连续 delta |
| AT16 | 同一快照/日志跨 Linux 与 Windows 重放 | 状态哈希相同；不通过的模块被限制恢复域或用 FullCheckpoint |
| AT17 | 游戏配置升级、包排空、恢复旧版本局、错误 schema | 旧局钉住版本；不兼容恢复明确失败；不盲降级 |
| AT18 | 新库安装、资料更新冲突、并发资产增减、进程崩溃 | 默认 provider 可用；余额/库存和流水一致；无 JSON 覆盖奖励 |
| AT19 | 快照写一半、最新快照损坏、旧快照重放、Finishing 恢复 | 原子可见完整快照；回退恢复或明确失败；结束阶段不重启战斗 Tick |
| AT20 | 结算到第 N 个观众时 kill，重复发送结果，FinalizeRound 任意位置崩溃 | 每笔一个账本效果；占位、挂载指针和 owner 原子释放，能够开启下一局 |
| AT21 | 活跃房间日志清理、去重窗口边界、磁盘告警 | 恢复链不断裂；未处置事件保留；压力不导致静默删除 |
| AT22 | 全集群停机冷启动、Control seed 不在线、Agent 重启、离线证书自举 | bootstrap 恢复入口和实例认证，不依赖在线 Control 先发证 |
| AT23 | ProcessReady 但房间恢复失败，PID 重用，旧报告迟到 | 两类状态分别展示；不误杀，不回退 incarnation |
| AT24 | 停掉全部 Control，恢复后重发旧计划 | 租约有效期内按契约继续，到期停止；旧计划不重复拉进程 |
| AT25 | 旧 owner 与 Control 分区但仍连 Data/客户端，新节点接管 | 旧 epoch 新写、资产命令和权威输出被阻止；历史合法提交可恢复 |
| AT26 | 主库断电、同步备库断联、旧主重新出现 | 无双写主库；已确认事务存在；不自动降级保证 |
| AT27 | DB commit 已完成但 RPC 响应丢失 | 原 OperationId 查询到原结果，无重复效果 |
| AT28 | 实际独立节点失电，100 房间同时恢复 | 报告包含检测时间的恢复分布；N+1 不足时正确拒绝/暂停 |
| AT29 | 两 OS 安装、服务重启、子进程孙进程、Agent 崩溃 | 正确回收进程树、包选择、资源能力报告和状态恢复 |
| AT30 | Gateway/Streamer/Game 排空中途再故障 | 会话或所有权按协议转移；回滚不破坏持久数据 |
| AT31 | 从礼物追踪至帧和奖励，执行受控恢复命令 | 跨服务 trace/receipt 可追溯，操作者和理由可审计 |
| AT32 | 错角色证书、错租户、重放凭据、泄密扫描 | 未授权请求被拒绝，日志不包含秘密 |

这些不是仅测试某个私有方法返回值的单元测试。涉及故障和幂等的场景必须验证数据库状态、客户端输出和副作用记录三者一致。

## 3. 实施阶段与交付件

### M0：契约与可运行骨架

交付：协议工程、模块边界、默认 PostgreSQL schema/迁移、DataServer、基本 ControlServer、NodeAgent 双 OS 骨架、安装配置和平台模拟器。先完成幂等回执、事务锁顺序、所有权 fencing 和 bootstrap。

出口：AT18/22/23/27 的基础部分及 AT32 身份隔离；Linux/Windows 均可从空库启动。不能以 mock 全部依赖宣称已可独立部署。

### M1：真实主播生命周期与平台接入

交付：两平台直播玩法专属适配器、Login/Resume、StreamerActor、挂载唯一约束、平台任务、持久收件箱、个人资料业务。

出口：AT01～09；真实平台无法联调时可完成模拟契约测试，但标记相应适配器 NotProductionReady，不阻塞其他实现，也不将其伪装为通过。

### M2：单节点完整对局

交付：确定性示例玩法、RoomActor、FrameStore、快照/重连、默认资产库存、结算、排行榜、双主播客户端示例。

出口：AT13～21、AT27 的单节点部分；必须演示一局从启动、输入、断线、重连到结算，不是仅演示 WebSocket 收发。

### M3：多节点匹配和业务恢复

交付：匹配预留/准备/提交、跨机路由、节点调度、Room/Streamer 接管、平台任务接管、Admin 状态和故障命令。

出口：AT10～12、AT24/25/28/31；独立机器网络隔离证明 fencing，不能用同进程多个对象替代。

### M4：生产部署与运维验收

交付：双 OS 安装包、签名包与升级、排空、HA 数据库手册、备份恢复、容量报告、安全测试和完整运维页面。

出口：AT16/17/26/29/30/32、完整基线负载与真实平台回归。只有在这些证据具备后宣称“生产可用”。

## 4. 容量验收报告模板

报告必须记录：硬件/OS/runtime/模块包、数据库与同步拓扑、总输入及热点分布、原始与合并事件数、状态大小分布、Tick 计算/提交分位数、WAL/磁盘/网络、队列年龄、恢复检测与重放耗时、丢弃类别及原因、结算完成延迟。

首轮模型为主设计第 11 章，不将历史 100 房间数字视作当前实测结论。未通过时调低声明容量或优化后重新测试，不删除失败样本。
