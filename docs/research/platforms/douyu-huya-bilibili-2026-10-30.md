## 三个平台在 Chorus 中的归属与兼容性检查

本表是对 [架构文档](../../architecture/architecture.md) 的研究映射，**不是三家官方要求，也不是已实现承诺**。

| 进程 | 接入时职责 | 三家适配必须核查的边界 |
| --- | --- | --- |
| PlatformGateway（PG） | 官方连接/回调、鉴权验签、解码及统一事件；按 ControlServer 下发的路由直达对应 GameServer 的 RoomActor；执行获授权的平台生命周期调用 | 斗鱼协议待取得；虎牙先确认迁移；B站先确认 client/server 权限。只信任可验证的应用/直播会话绑定，不接受客户端随意指定房间 |
| ControlServer（CS） | 绑定目录、匹配与房间分配、房间 owner epoch、版本化路由及 Gateway ACK、结束/恢复编排 | 平台直播间、平台场次与内部 RoomId/局次不是同一 ID。路由须携带平台/应用/直播会话/绑定代次/房间/owner epoch；不能用玩家昵称定位 GS |
| GameServer（GS） | RoomActor 校验并接收统一输入，权威 tick/业务行为、去重结果及提交后广播 | 平台事件影响哪个 tick、迟到事件/重连重放/房间迁移策略需显式定义；平台无唯一事件 ID 时暴露能力缺口 |
| StreamerGateway（SG） | 主播客户端 WSS、认证会话和房间路由、输入/帧及快照转发 | Unity 平台启动流程与 Chorus 会话连接衔接；主播断线不让其成为服务端平台事件可信来源 |
| StreamerServer（SS） | 主播账号/平台身份、验证后直播绑定注册、匹配意图和个人数据 | 开播/下播/授权撤销更换绑定；客户端启动参数须后端校验后才能注册给 CS |
| DataServer（DS） | 显式数据读写、事务、唯一键/去重及版本约束 | 可保存绑定/事件审计/结果等数据；不负责解析平台原始事件、选择房间或编排平台结束 |
| NodeAgent | 主机资源与进程/包管理 | 平台 Unity 包运行位置和云启动产品与 NodeAgent 托管服务端不是同一职责；不承担平台业务匹配或事件分发 |

共同开局门槛：取得可信绑定 → CS 分配/确认房间和 owner → 安装事件路由并取得 ACK → 按平台规则完成 start/订阅等前置条件 → 才进入业务战斗。各平台 start 与路由准备的具体先后应按当前官方 contract 细化，不能抄成通用固定调用顺序。

共同收尾门槛：最终结果已提交 → PG 停止投递并完成在途排空确认 → CS 授权平台结束/查询补偿 → 确认平台结果及结算完成 → 释放绑定/路由并授权销毁房间。平台硬超时/强制结束和调用结果未知应进入补偿状态，不得把 HTTP 超时等同于“平台结束成功”。
