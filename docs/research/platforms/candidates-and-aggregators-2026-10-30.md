## 与 Chorus 的共同兼容条件

以下为对现有职责边界的兼容性分析，属于项目设计判断，不是来源平台对 Chorus 的背书。

| 核查主题 | 接入前应拿到的证据 / 结论 | 对应 Chorus 边界 |
| --- | --- | --- |
| 可信来源 | 官方签名回调、授权服务端连接或可核验事件；明确测试/模拟标志 | PG 负责协议和验签；U3D、直播伴侣或聚合工具客户端不能自行权威转报付费礼物 |
| 房间绑定 | 平台、应用、主播、直播间、玩法实例标识的作用域和授权关系 | ControlServer 同步经过确认的直播绑定与路由；PG 再直接投递目标 GameServer / RoomActor，不能按用户自报目标路由 |
| 所有权与顺序 | 稳定源事件 ID、连击累计/增量含义、重试、乱序、回放窗口 | 保留原始语义，按平台+应用划分去重域；房间 epoch 用于隔离旧所有者，tick 才是房间模拟进度；平台时间戳不代替二者 |
| 结束与迟到事件 | 是否有玩法关闭 API、成功/失败/未知结果、回调延迟、重试上限 | ControlServer 先等待 PG 停投确认，再调用已授权的平台关闭流程；结果未知不默认为成功。没有官方关闭接口时明确记录缺口，不能虚构远程 ACK |
| 礼物与结算 | 付费/免费礼物、货币、赠订、退款和撤销字段；结算数据的权威来源 | 游戏行为与财务事实分开；DataServer 只执行明确的数据读写，不承接平台解析或事件业务分发 |
| 指标 | 原始消息、批次、标准事件、去重丢弃、验签失败、路由拒绝、投递成功的口径 | 每平台、应用、直播间单独统计；包数不等于礼物数，也不承诺从平台观看人数获得 Chorus 在线玩家数 |
| 身份与跨平台匹配 | 平台用户 ID 作用域、匿名行为、账号关联授权 | 默认不合并跨平台玩家、不开放跨平台主播匹配；匿名事件的归属必须由玩法策略明示 |
| 使用范围 | 目标地区、应用审核、商业化、SDK 许可与游戏用途 | 通过技术连接测试不代表已经获得游戏上线或运营资格；本页不改变抖音/快手的实施范围 |

## 后续收集物料的验收单元

每个平台分别形成一份资料包，各项可独立验收，不以“调研完成”替代缺口说明：

1. 官方入口与产品主体：记录可访问链接、页面标题、原始发布日期（有则记录）和复核日期。
2. 权限与用途：记录目标应用类型、地区、主体要求、直播间授权方式以及是否明确允许该类玩法。
3. 事件目录：逐项确认评论、点赞、礼物、关注、入场、直播结束；未开放和未证实分开标记。
