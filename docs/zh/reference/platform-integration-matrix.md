# 多直播平台接入资料与架构兼容性

**资料核查日期：2026-10-30（Asia/Shanghai）。** 本页记录公开资料调查，不代表已取得开发者权限、SDK 商用许可或通过真实平台联调。平台来源的发布／修改日期与本次访问日期分开保存在下列证据附件中；未显示来源日期的标为未知，不推断为最新版本。

本期实施范围仍为 **抖音、快手**。下一阶段重点调查斗鱼；虎牙、B站及其他平台只做资料与兼容性研究。第三方覆盖清单、用户规模、分账比例、关键词或礼物限制，没有适用产品和官方证据时均不作为确定事实。

## 架构兼容性

这是相对于[当前目标架构](/architecture/architecture)的资料评估，**不是实现验收**。平台可能需要额外协议适配，但不因此增加新的业务进程或把平台业务下放到 DataServer。

| 现有边界 | 可复用部分 | 必须逐平台确认的缺口／变更 |
| --- | --- | --- |
| StreamerServer + Unity | 主播实体、授权绑定、提交匹配意图；Unity 共用连接与同步接口 | 真实身份作用域、伴侣启动／授权 SDK、SDK 版本和线程回调；只有抖音／快手进入本期条件编译 |
| PlatformGateway | 验证来源、平台归一化、按 ControlServer 已确认路由直推 GameServer | HTTP／WS／流接收适配、签名、订阅持有方、平台事件键及补发；有客户端 SDK 不代表客户端转报可信 |
| ControlServer | 绑定代次、RoomId、owner／RoomEpoch、路由安装确认、匹配及收尾协调 | 平台直播场次与游戏对局映射、平台 start/end 调用方及未知结果恢复；不得猜测玩家所在房间 |
| GameServer / RoomActor | 每房间 Tick、权威执行、已提交效果、重连追赶 | 礼物连击／点赞聚合的业务语义；平台传输重推不得生成重复奖励；平台 PK 不替代帧同步 |
| DataServer | 明确的绑定／输入／幂等／状态存储事务与所有权隔离 | 数据字段、键长度、保留期及事务约束；不解析平台事件、不选择目标房间、不编排平台 API |
| StreamerGateway | 主播客户端输入与已提交帧直连 GameServer | 不承担平台礼物来源证明；客户端连接和平台事件连接分开恢复 |
| NodeAgent / 后台 | 机器、进程和资源监控；后台汇总平台指标 | NodeAgent 不持有房间权威；榜单后台需区分平台榜与框架榜；包数、事件数、礼物件数分别统计 |

统一身份链为：`Platform + AppId + 已验证主播身份 / 直播场次 → BindingId/Generation → RoomId → owner/RoomEpoch`。平台观众事件先归属已验证直播挂载，不能用昵称或平台房间号猜测 GameServer。跨房 PK 与跨平台组局不是同一权限；跨平台匹配和身份合并默认不启用。

结束顺序继续遵守：提交终局 → ControlServer 关闭投递 → PlatformGateway 排空并确认 → 按授权责任通知平台并确认结果 → 结算／处置剩余输入 → 释放资格 → 授权销毁房间。某平台不要求结束接口时，必须有证据才能标记 NotRequired；接口超时不能视作成功。稳定事件键、可信入口或关闭确认缺失时，应记录阻塞及替代方案待决。

抖音、快手的协议差异可通过平台适配与生命周期契约承载，但仍需真实权限和联调。斗鱼因关键物料未齐暂为“证据不足”；虎牙旧路线有停用风险须先核实替代通道；B站长连接需落实到新 PlatformGateway 与生命周期协调。其他候选的单项公开 API 不能直接推出整个游戏接入兼容，逐项结论见附件。
