# 开箱即用的开发能力：排行榜优先

2026-10-29 目标交付清单。框架应提供默认实现、迁移、业务接口、客户端查询示例、重试规则及可执行验收，不能要求玩法自行拼装存储。首项为排行榜；其余资料、资产库存、结算、会话恢复、GM 和可观测能力沿用各自实施项，不在此扩大成未经定义的功能集合。

## 当前已有的排行榜基础

`RedesignSettlementStore` 已有按 tenant/game/board/player 保存的积分投影：奖励事务内累加分数，`ReadLeaderboard` 返回 TopN，排序为 score 降序、player_id 升序。它是基础实现，不是已完成的通用排行榜产品。它目前将分数与奖励 delta 耦合，缺少完整周期、主体类型、个人名次及稳定分页契约；旧版排行榜功能不能直接折算为新架构通用能力。

## 默认玩法接入

玩法通过服务端已提交的结果/效果提供排名变更意图，例如“本局积分累加”或“本局最高分”，业务排行模块验证后请求 DataServer 保存投影。默认不要求玩法持有数据库凭据。不能把客户端上报分数、礼物金额或任何资产增减自动视为榜分。

建议提供 `RecordScoreEffect`、`GetTop`、`GetRank`、`GetAroundMe`、`GetEntry`；这些是目标 API 名称，并非已存在的可调用 SDK。通过已提交效果的不可变 EffectId/GrantId 幂等投影，重试、恢复、重放都不能重复加分；按提交来源重建榜单也不能重发奖励。

## 排行榜定义

| 配置 | 默认与要求 |
|---|---|
| 标识 | TenantId + GameId + BoardId + PeriodId + ScopeId，不能跨租户串榜 |
| 排名主体 | 显式 Player / Streamer / Faction；默认 Player，不混用主播与观众身份 |
| 计分 | 初期 Sum 与 Max，整数分值；负分/扣分须显式允许，边界与溢出校验 |
| 排序 | 分值降序、稳定主体 ID 升序；默认唯一顺序名次，不能把并列策略留给数据库偶然顺序 |
| 周期 | AllTime 为默认；日/周/赛季按明确时区、起止边界和版本计算，不能在线清空旧榜冒充换期 |
| 作用域 | 默认游戏全局；直播场次或房间榜显式指定 ScopeId，跨平台账号合并不自动开启 |
| 查询 | TopN、个人名次、附近名次；有限页大小；分页绑定榜单读取版本，榜变更时明确要求重启读取 |
| 可见性 | 查询校验租户/游戏/身份，展示信息裁剪；敏感资料不随榜单输出 |
| 重置与修正 | GM 指定 board/period/scope，预期版本、操作 ID、理由、审计；不得直接清除原始积分来源证据 |
| 生命周期 | 周期截止、投影待处理、冻结、归档分开；迟到结算明确归属原周期或拒绝，不按重试时间换榜 |

实时变化榜的个人名次必须对应同一次读取视图。分页实现可返回有期限的快照版本/游标；快照失效显式错误，不返回跨版本看似连续的名次。最终结算榜以冻结版本为准，奖励引用不可变清单，不能反复查询变化的 TopN 发奖。

## 进程职责

玩法 GameServer 产生已提交计分效果；ControlServer 内的业务排行/结算执行模块校验来源、选择 board/period/scope、驱动投影或重建；DataServer 执行明确榜单键和数值变更的幂等读写事务。StreamerServer / Gateway 提供授权后的查询与展示。平台排行榜上报仍由 PlatformGateway 的独立授权任务执行，内部榜成功不代表平台榜已成功。

首期排行榜模块不新增独立进程。实现必须提供默认 PostgreSQL provider、schema 迁移及一个示例玩法：开局→提交计分→终局投影→TopN/个人名次→重复结算不重复加分→换期旧榜可查。尚未实现的能力由 TODO 单独验收。
